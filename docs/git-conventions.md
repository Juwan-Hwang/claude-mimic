# Observed Git Conventions & Attribution Engineering Patterns

This reference documents verified Git pull request and commit conventions observed across open-source engineering workflows, providing architectural archetypes for AI coding agents.

---

## 1. Pattern 1: Systems & Low-Level Infrastructure

Demanding systems programming environments (operating system components, runtime libraries, low-level networking, wire protocol parsers):

### Commit Conventions:
- Causal explanation: Precisely explains the failure mode, signal handling, or race conditions.
- Trailer form: Canonical RFC 2822 dual-author trailer.
```text
fix(signal): persist session context across process interruptions

Under POSIX signal delivery, asynchronous interrupts aborted active worker
threads without flushing intermediate ring buffers. Register a dedicated
signal handler that drains buffered events before shutdown.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

**Key Takeaway**: Low-level systems commits prioritize causal explanation (why the interrupt occurred) over reciting diff lines.

## 2. Pattern 2: Enterprise Monorepos & Multi-Turn Branches

Large multi-developer repositories managing complex feature branches across multiple tasks and agent turns:

### Turn-Based Multi-Commit Architecture:
- Individual commits preserve the exact model identity active for each turn:
  - Heavy algorithmic refactors / large-diff reorganization:
    ```text
    Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
    ```
  - Autonomous module architecture & domain planning:
    ```text
    Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>
    ```
  - Routine integration tests & endpoint implementations:
    ```text
    Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
    ```
- **Merge Commits**: Merge commits (`Merge pull request #...` or `Merge branch ...`) **never receive trailers**.
- **Historical Integrity**: Never rewrite or homogenize earlier commit trailers when adding a new turn to an existing branch.

## 3. Pattern 3: Remote Web Sessions & Dual-Trailer Pairing

Environments operating through web interfaces, remote containers, or hosted dev boxes:

### Commit Trailer Shape:
- `Co-Authored-By:` followed immediately on the next line by `Claude-Session:` (separated by a single newline, no blank line in between):
```text
feat(metrics): add per-tenant throughput breakdown table

Aggregates windowed event throughput across active tenants for real-time
capacity planning.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_01U7vy96qF63BugmboFm2wPw
```

## 5. Pattern 5: GitHub UI Web Integration & Identity Truth

### Co-Author Attribution Mechanics:
- GitHub resolves `noreply@anthropic.com` to the verified GitHub account `claude`.
- When commits carrying `Co-Authored-By: ... <noreply@anthropic.com>` land on GitHub, the web interface renders:
  **"Author and claude committed"** with the official Claude avatar.
- **Header Chip vs. Commit Text**: In GitHub's commit overview list, the model display name (e.g. `Claude Opus 5`) is NOT rendered in the author header chip — it appears strictly inside the raw commit message body when inspected.
- **Local Author Invariant**: In all local CLI runs, the `Author` and `Committer` headers belong 100% to the human user (`user.name` / `user.email`). Claude NEVER replaces the human author locally.

### Automated GitHub Actions Runner (`claude[bot]` — Observed via GitHub API):
- Automated CI actions executing under the official Anthropic Claude GitHub App (as observed on GitHub REST API) use:
  - Bot User ID: `209825114`
  - GitHub App ID: `1236702`
  - Committer email: `209825114+claude[bot]@users.noreply.github.com`
- Direct human-assisted CLI commits always use the human developer as the Git author and append `Co-Authored-By: Claude <Model> <noreply@anthropic.com>`.

## 6. Pattern 6: Advanced Edge Cases & Synchronization Dynamics

### Revert Commits:
Standard `git revert` commits retain canonical C1 model attribution:
```text
Revert "feat(wire): introduce binary frame compression"

This reverts commit a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

### Downstream Maintainer Rebase Dynamics:
When repository maintainers cherry-pick or rebase a PR branch into the primary trunk:
- Git preserves the original human contributor as `Author` (`Author: <contributor>`).
- Git updates `Committer` to the merging maintainer (`Commit: <maintainer>`).
- The `Co-Authored-By: Claude <Model> <noreply@anthropic.com>` trailer remains intact at the bottom of the commit message.

### Automated Workspace Sync Identities:
In automated background sync tasks or directory synchronizer operations, the commit author is recorded as:
- `Claude Code file sync <noreply@anthropic.com>`
- `Claude Code directory sync <noreply@anthropic.com>`
