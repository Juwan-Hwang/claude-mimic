# Pull Request Signatures & Attribution Mechanics

This reference defines the 8 pull request signature patterns used in Claude Code formatting, specifying exact syntax, surface mappings, branch conventions, and emission conditions.

---

## 1. The 8 Pull Request Signature Forms (P1–P8)

### Form P1: Standard Default (Unadorned) — Primary CLI Default
The standard clean signature:

```markdown
🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

> [!IMPORTANT]
> **Default Directive**: Standard local CLI pull requests default to this clean unadorned signature unless operating in a web/remote session environment.

---

### Form P2: Enhanced Attribution (`N-shotted` & Telemetry) — Opt-In Only
Generated in automated `/commit-push-pr` command flows when session telemetry is active:

```markdown
🤖 Generated with [Claude Code](https://claude.com/claude-code) (93% 3-shotted by claude-sonnet-5, 2 memories recalled)
```

- **Fallthrough**: When all telemetry values are zero, it cleanly falls back to Form P1.
- **Model Name Scope**: External repositories show desensitized family short names (`claude-sonnet-5`, `claude-opus-4`), while internal repositories may display versioned IDs (`claude-opus-4-8`).
- **Advisory**: Keep Form P1 as default unless explicitly instructed.

---

### Form P3: Surface Attribution (`via <Surface>`) — Opt-In Only
Emitted when operating through a designated surface environment:

```markdown
🤖 Generated with [Claude Code](https://claude.com/claude-code) via Cowork
```

> [!CAUTION]
> **Hard Gate & Public Rarity**: In official Claude Code, feature flag `tengu_pr_footer_surface_suffix` defaults to `false`. Emitting `via <Surface>` in public PRs is practically non-existent in authentic traffic (~14 total occurrences across GitHub). **Never emit `via <Surface>` unless explicitly requested by the user.**

### Form P4: Remote Web Session (Dual PR Footer + Claude-Session Trailer)
Emitted when running in a hosted web bridge or remote container (`claude.ai/code`).

- PR Body:
  ```markdown
  🤖 Generated with [Claude Code](https://claude.com/claude-code)

  https://claude.ai/code/session_01U7vy96qF63BugmboFm2wPw
  ```
- Git Commit Trailer (separated by single `\n`):
  ```text
  Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01U7vy96qF63BugmboFm2wPw
  ```

> [!NOTE]
> **Dual Trailer Invariant**: When both are present in commits, the order is fixed: `Co-Authored-By:` first, `Claude-Session:` second. The client validator accepts `^(cse_|session_)[A-Za-z0-9_-]{1,128}$`, while the standard server convention produces `session_01` followed by 22 Bitcoin Base58 characters (`session_01[1-9A-HJ-NP-Za-km-z]{22}`).

### Form P5: Pre-Q3-2025 Legacy Product URL (Opt-In for Historical Parity)
Emitted when contributing to pre-Q3-2025 legacy branches:

```markdown
🤖 Generated with [Claude Code](https://claude.ai/code)
```

---

### Form P6: Attribution Suppressed / Opt-Out Mode (colloquially "Undercover")
Completely omits footer signatures (`attribution.pr: false` / `pr: ""`) and Git commit trailers (`includeCoAuthoredBy: false` / `attribution.commit: ""`) when repository policy or user configuration prohibits AI attribution. *(In internal Anthropic employee builds, this is controlled by `isUndercover()`; in public Claude Code releases, it is executed via standard settings `includeCoAuthoredBy: false` or `attribution.commit: ""`)*.

---

### Form P7: Remote Web Client Session-Only (Bare Session URL)
Emitted when `Co-Authored-By` is suppressed in web container sessions:
- PR Body: `https://claude.ai/code/session_<id>`
- Git Commit Trailer: `Claude-Session: https://claude.ai/code/session_<id>`

---

### Form P8: Hosted Web Session / GitHub App Attached Signature
Generated by hosted cloud web sessions and the Claude GitHub App (`claude[bot]`) (not by the local CLI binary):

```markdown
🤖 Generated with [Claude Code](https://claude.com/claude-code)

https://claude.ai/code/session_01U7vy96qF63BugmboFm2wPw

---
_Generated by [Claude Code](https://claude.ai/code/session_01U7vy96qF63BugmboFm2wPw)_
```

- **Structure**: Form P1 standard signature, followed by a blank line, the bare session URL, a horizontal rule `---`, and an italicized attribution markdown link pointing directly to the session URL.

### Pre-Wrapped Changelog Block (Body Modifier before Signature)
Opt-in format for repositories that explicitly mandate pre-wrapped release notes in PR descriptions (retired from default prompts in v2.1.270):

```markdown
## Summary
- Upgrades stream parser to reject invalid EOF payloads.

## Test plan
- [x] Run unit test suite: `cargo test`

## Changelog
<!-- CHANGELOG:START -->
- fix(stream): reject invalid EOF payloads during handshake
<!-- CHANGELOG:END -->

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

> [!IMPORTANT]
> When present, the `## Changelog` block must always precede the signature.

### Two Legitimate Trailer Positions in PR Body
In GitHub pull request bodies, attribution trailers are observed in two legitimate structural positions:

1. **Trailer Before Signature (Squash-Merge & Import Flow)**:
   The RFC 2822 trailer appears before the robot footer. This occurs when commit message bodies are carried into the PR description or when repositories configure `squash_merge_commit_message = PR_BODY`:
   ```markdown
   ## Summary
   - Fixes stream stall on EOF.

   ## Test plan
   - [x] Run test suite

   Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>

   🤖 Generated with [Claude Code](https://claude.com/claude-code)
   ```

2. **Trailer After Signature (Trailing Metadata Injection)**:
   The trailer appears at the very bottom, below the robot signature:
   ```markdown
   ## Summary
   - Fixes stream stall on EOF.

   ## Test plan
   - [x] Run test suite

   🤖 Generated with [Claude Code](https://claude.com/claude-code)

   Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
   ```

Both formats are authentic. CLI default standard output places the robot signature at the end.

### Observed Wild Non-Standard Variants (Recognition Only)
Occasionally encountered when inspecting pull requests created by non-standard third-party tools or wrappers:
1. `🤖 _Generated with [Claude Code](https://claude.ai/code) — Claude Opus 5_` (emoji + italicized link + em-dash + model name)
2. `🤖 Generated with Claude Code` (plain unlinked text)

*Guidance*: Agents should recognize these patterns when reviewing existing PRs, but must never generate them when emulating official Claude Code CLI output.

### Form IV: GitHub App / Actions Execution (`claude[bot]`)
When running inside automated GitHub Actions workflows via the Claude GitHub App (Bot User ID `209825114`):
- **PR Author**: `claude[bot]`
- **Commit Author**: `claude[bot] <209825114+claude[bot]@users.noreply.github.com>`
- **Typical Trailers**:
  ```text
  Co-authored-by: <Human Author> <<user>@users.noreply.github.com>
  Co-authored-by: Claude Sonnet 4.6 <noreply@anthropic.com>
  ```

---

### Form V / C7: Cloud Runner Automated Hook Path
In cloud runner environments where an automated git hook runs:
- **Author Identity**: The runner sets Claude as the commit author: `user.name=Claude`, `user.email=noreply@anthropic.com` (SSH signed).
- **Trailer Injection**: The runner hook injects the human user's session account:
  ```bash
  git interpret-trailers --in-place --if-exists addIfDifferent --trailer "Co-authored-by: $name <$email>"
  ```
- **Trailer Result**:
  ```text
  Co-authored-by: <user-name> <<user-email>>
  ```

## 2. Branch Naming & Product Alignment

### Branch Naming Conventions:
- **Local CLI Workflow**: `username/feature-name` (from `SAFEUSER` environment variable, falling back to `whoami`).
- **Remote Web / Hosted Workflow**: `claude/<task-slug>-<6-char-id>` (e.g. `claude/schoolpark-production-check-jswz7f`).

### Product URL Alignment:
| Period | Canonical Product URL | Use Case |
| :--- | :--- | :--- |
| **Modern Default** | `https://claude.com/claude-code` | Standard for modern commits & PRs |
| **Legacy Opt-In** | `https://claude.ai/code` | Only when contributing to repositories strictly using legacy URLs |

### Managed Attribution Hierarchy:
When operating under enterprise policies (`managedCommit`, `managedPr`):
- Managed lines apply unconditionally and cannot be overridden by user instructions or `.claude/settings.json`.
- Non-managed lines adhere to repository rules (`CLAUDE.md`) or user preferences.
